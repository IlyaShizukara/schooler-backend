# ЕГЭПро — Auth API (Telegram-логин)

Небольшой сервис на FastAPI, который связывает Telegram-бота с приложением:

1. Приложение просит код: `POST /api/auth/start` → получает `code` и `deep_link`
   вида `https://t.me/ВашБот?start=code`.
2. Приложение открывает `deep_link` (Telegram открывается сам, если установлен).
3. Пользователь жмёт **Start** в боте → бот получает его `first_name`, сохраняет
   в БД и помечает код как `confirmed`.
4. Приложение всё это время опрашивает `GET /api/auth/session/{code}` раз в
   пару секунд и, увидев `status: confirmed`, забирает `name` и показывает его
   на приветственной карточке.
5. Код можно сохранить локально (в приложении) и использовать как простой
   токен сессии — при следующем запуске `GET /api/auth/session/{code}` сразу
   вернёт имя без повторного логина.

## 1. Создать бота

Уже есть токен — отлично, но для справки:
1. Написать [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Задать имя и юзернейм (например `EgeProAuthBot`).
3. Скопировать токен вида `123456789:AA...`.

## 2. Поднять PostgreSQL

Локально проще всего через Docker:

```bash
docker run --name egepro-db -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=egepro -p 5432:5432 -d postgres:16
```

Таблицы создаются автоматически при первом запуске сервиса (через
`Base.metadata.create_all`) — отдельно ничего накатывать не нужно. Если
проект пойдёт в продакшн, стоит перейти на Alembic-миграции.

## 3. Настроить окружение

```bash
cd backend
cp .env.example .env
# впишите в .env: BOT_TOKEN, BOT_USERNAME, DATABASE_URL
```

## 4. Установить зависимости и запустить

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

uvicorn main:app --reload --port 8000
```

Бот стартует **в том же процессе** через long polling — отдельно его
запускать не нужно. Если увидите в логе `Application started`, значит и
API, и бот подняты.

Проверка: `curl http://127.0.0.1:8000/api/health` → `{"ok": true}`.

## Эндпоинты

| Метод | Путь                          | Что делает |
|-------|-------------------------------|------------|
| POST  | `/api/auth/start`              | Создаёт код авторизации + ссылку на бота |
| GET   | `/api/auth/session/{code}`     | Статус кода: `pending` / `confirmed` / `expired`, при `confirmed` — имя |
| GET   | `/api/health`                  | Проверка живости сервиса |

## Важно про безопасность (для продакшна)

Это рабочий, но упрощённый вариант, подходящий для пет-проекта/MVP:

- Код авторизации после подтверждения используется как бессрочный токен
  сессии. Для реального продакшна разумно завести отдельный `session_token`
  (JWT или случайную строку с TTL и refresh-механизмом), а `code` использовать
  только на этапе логина и сразу инвалидировать.
- Сейчас `CORS_ORIGINS=["*"]` — на проде укажите конкретный домен фронтенда.
- Для нагрузки выше пары тысяч пользователей вместо long polling у бота лучше
  настроить вебхук (нужен HTTPS-домен).
